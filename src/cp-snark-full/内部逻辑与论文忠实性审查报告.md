## 二、【重点】承诺权重编码 vs R1CS witness 权重编码（Scalar / dalek）

> **标注：** 本节即对话中讨论的 **「统一 Scalar 嵌入 / 承诺–witness 一致性」** 问题（文档 `docs/CP-SNARK自检与计算量预估.md` 中的 **P0**），**不是**曲线嵌入（$n_2=q_1$）问题。  
> 两条路径均在 **同一标量域** $\mathbb{Z}_{q_1}$（Ristretto255 / `curve25519-dalek`）；`libspartan::scalar::Scalar` 即 dalek 标量的再导出。

### 2.1 两条路径对照

| 环节 | 类型别名 | 编码 API | 代码位置 |
|------|----------|----------|----------|
| **承诺侧（cp-snark-full 新增）** | `libspartan::scalar::Scalar` | `embed_u128_to_scalar` → `Scalar::from_bytes_wide`（u128 写入 64 字节小端低位，再 mod $q_1$） | `curve.rs:49-53` → `commitment.rs:61` → `protocol.rs:126`（验证重算） |
| **Witness 侧（原仓库，未改）** | `curve25519_dalek::scalar::Scalar`（与上为同一底层类型） | `Scalar::from(u128)`（dalek 对小整数的标准嵌入） | `point_mult.rs:335-336`（经 `#[path]` 复用） |

```49:53:src/cp-snark-full/src/curve.rs

    let mut wide = [0u8; 64];
    wide[..16].copy_from_slice(&value.to_le_bytes());
    Scalar::from_bytes_wide(&wide)
}
```

```334:336:src/proof_generation/vPIN_proof_generation/src/point_mult.rs
        number = weight_list[j] as u128;
        a[j] = Scalar::from(number);
```

### 2.2 语义关系

- **域相同：** 均为 Ristretto255 标量域 $q_1 = 2^{252}+277423\ldots989$。
- **API 不同：** `from_bytes_wide`（宽字节归约）与 `Scalar::from(u128)`（dalek `From` 实现）在数学上对 **$m \ll q_1$ 的 u128 权重** 通常给出**同一域元素**，但 **32 字节 `to_bytes()` 是否一致** 未在仓库内用测试锁死。
- **验证未桥接 witness：** `verify_model_commitment` 只比对 `digest_hex = SHA256(承诺侧 scalar.to_bytes())`，**不**读取 Spartan 证明中的 `vars_para`，**不**证明「承诺权重 = R1CS 中打开的权重槽」。

```160:164:src/cp-snark-full/src/commitment.rs
pub fn verify_model_commitment(model: &ModelCommitmentBundle, weight_scalars: &[Scalar]) -> bool {
    model.num_weights == weight_scalars.len()
        && model.cm_weights.digest_hex == scalars_digest(weight_scalars)
}
```

### 2.3 风险等级与建议

| 项 | 评估 |
|----|------|
| 对当前 `rust_files/A/weight.json`（178 项 u128） | 大概率一致；**未**有单元测试 |
| 对论文「cm 绑定 witness」语义 | **不满足**（缺电路级等式 + 缺 Pedersen 打开） |
| 建议 | P0：在 cp-snark-full 内对典型权重断言 `embed_u128_to_scalar(w).to_bytes() == Scalar::from(w).to_bytes()`；或 witness 侧改为与承诺同 API（需 wrapper，**不宜**直接改 `point_mult.rs`） |
| **2026-06-04** | ✅ 已实现：`curve::u128_encoding_matches_witness` + `cargo test`（含 network A 全 178 权重）；规范编码为 `embed_u128_to_scalar` |

## 三、承诺与验证机制（cp-snark-full 新增）

### 3.1 非论文 CPS.Comm

- `commit_model` / `commit_public_inputs` 使用 **SHA256 摘要 + 自定义 hash-to-scalar Pedersen**，非 libspartan 论文中的 `CPS.Comm` 多项式承诺。
- `point_hex`（Ristretto 点）写入 transcript，但 **`decompress_commitment` 无调用方**，验证**不**做 Pedersen 打开。

### 3.2 cm_W 范围

- 仅 `load_weights_only()` → `weight.json`（如 network A 为 **178** 个标量），**不是**完整 CNN `.npy` 参数张量。

### 3.3 cm_x 范围

- `public_inputs_for_network()` 仅嵌入 E₂ Weierstrass 系数 **a**（1 个标量），**不**含客户端图像、定点明文或密文。

### 3.4 验证方依赖 prover 本地文件

- `verifier_run` 从 `rust_files/{network}/pointMult/weight.json` **重新读取**权重并算 digest，非「客户端仅持 `protocol.json` 中的 cm」的独立验证模型。

### 3.5 e2_weights_digest

- 哈希混入 `curve_order`（论文 **$q_2$** / 代码 `curveOrder`），与嵌入用的 **$n_2=q_1$**（`curveBaseField`）语义不同；属辅助绑定，易与曲线嵌入结论混淆。

## 四、挑战与 RLC（cp-snark-full 新增）

### 4.1 `gamma_add` / `gamma_mult`

- `ClientChallenge` 采样并写入 Merlin transcript（`challenge.rs:63-72`）。
- **`rlc_bind_scalars` 仅使用 `gamma`**，对 `gamma_add` / `gamma_mult` **无计算引用** → 与论文卷积/点运算的随机线性组合 **不对齐**。

### 4.2 `rlc_binding_hex`

- 公式：$\gamma \sum w + (1-\gamma)\sum a$（权重标量与与公开输入标量之和），存于 SNARK **外** 的 `protocol.json`。
- 与 R1CS witness、子电路证明 **无密码学绑定**（仅 prover/verifier 本地重算一致）。

### 4.3 Transcript 域

| 组件 | 标签 |
|------|------|
| 原 `proof_point_mult.rs` | `b"snark_example"` |
| cp-snark-full | `b"cp_snark_vpin"` + cm + challenge |

同一 R1CS 实例的证明 **不能** 与原二进制互验（预期行为，需在集成时统一入口）。

## 五、协议编排与其它工程问题

### 5.1 cm 与 R1CS

- `append_commitments_to_transcript` 将 cm .digest / point_hex 编入 FS transcript，**不改变** R1CS 可满足性语义；**无**约束将 `vars_para` 与 cm 等式连接。

### 5.2 `main.rs` `prove` 子命令

```71:80:src/cp-snark-full/src/main.rs
            let (num_adds, _, _, _, _) = cp_snark_full::load_data::load_data(network);
            let (num_adds2, _, _, _, _, _) = cp_snark_full::load_data_add::load_data_add(network);
            let challenge = ClientChallenge::sample(num_adds2, num_adds);
```

- `load_data` 首元为**点乘个数**，变量名 `num_adds` **易误导**；实际传入 `sample(num_adds2, num_adds)` 结果正确。

### 5.3 `run_full_protocol` 计时

- 先将 `verify_time_ms = prove_time_ms`，再第二次 `verifier_run` 更新 → 阅读 `protocol.json` 时需注意。

### 5.4 `python/run_protocol.py`

- 打印 `[Setup] E2 curve order n_2 = {curveOrder}`：**命名错误**；论文 $n_2$ 应对应 `curveBaseField`，`curveOrder` 为 $q_2$。

### 5.5 L2 / L4 跳过点乘

- 与 `vPIN_proof_generation/src/main.rs` **一致**，属原仓库行为，非 cp-snark-full 引入。
