# vPIN 平台隐私保护

> **文档性质**：基于 [vpin-平台顶层抽象架构.md](./vpin-平台顶层抽象架构.md) 平面三（隐私保护）及跨平面隐私边界的专篇，描述**保护对象**、**可见性域**、**五类机制保证**、**角色矩阵**与**用户可控项**。完整性核验见平面四与 [数据流图](./vpin-平台数据流图.md) 阶段 C。  
> **关联文档**：[平台数据流图](./vpin-平台数据流图.md)、[独立客户端与服务端协议合规](./vpin-平台架构-独立客户端与服务端（协议合规）.md)。

## 1. 隐私保护定位

vPIN 的隐私目标不是「服务端绝对不见任何比特」，而是在**可验证隐私推理**前提下：

1. **最小化明文暴露面**：用户明文输入与中间激活仅出现在**客户端可信域**或用户指定的**推理交互方**明文域；
2. **无头推理服务密文专属**：推理服务数据面不承载用户明文 I/O；
3. **可审计、可复核**：隐私边界与数据绑定由双验证器与客户端本地复核共同约束；
4. **用户可选权衡**：通过密态隐私模式在通信、推理、密态加载与安全之间表达倾向（§4）。

隐私平面（平面三）与完整性平面（平面四）**分工协作**：平面三定义**应保护什么**；平面四验证**是否被篡改或伪造**。

---

## 2. 隐私对象

| 对象 | 保护目标 | 主要威胁 |
|------|----------|----------|
| **原始输入** | 像素、token、多模态载荷不对无头推理服务以明文暴露 | 服务端日志、恶意 API、合谋 |
| **中间激活** | 层间特征不以明文驻留于无头推理服务 | 侧信道、错误卸载、持久化 |
| **推理行为** | 单次请求输入—输出关联不被跨会话持久画像 | 行为分析、关联攻击 |
| **托管数据** | OVDS 分片仅经 ACL 授权读出；链路加密 | 未授权 query、链路窃听 |
| **模型权重隐私** | HE：公开权重或承诺；MPC：分片不单方还原（*待扩展*） | 模型窃取 |

## 3. 可见性域（`PrivacyPolicy`）

平台用三个可见性集合抽象**谁可以看见什么**：

```
plaintext_zone()   -> { client_local, inference_peer }   // 明文可出现域
server_visible()   -> { ciphertext, public_weights, binding_meta, proof_artifacts }
custody_visible()  -> { signed_chunks, indices, ovds_proofs, no_plaintext_export }
```

### 3.1 按角色可见性矩阵

| 数据类型 | 客户端 | 推理交互方 | 无头推理服务 | 信任托管服务器 | 验证对象 |
|----------|--------|------------|--------------|----------------|----------|
| 用户明文输入 | ✓（本地） | ✓（仅 P3 非线性环节） | ✗ | ✗（默认） | ✗ |
| 输入承诺 / 摘要 | ✓ | 可选 | ✓（P2 控制面） | ✓（绑定元数据） | ✓ |
| 密文 / 秘密分片 | ✓ | ✓ | ✓（数据面） | ✓（代行交互时） | 日志审计 |
| 解密私钥 | ✓ | ✓（本地或托管密钥域） | **✗** | 视部署 | ✗ |
| 公开模型权重 | ✓ | ✓ | ✓ | ✓ | ✓ |
| OVDS 分片明文内容 | ✓（授权读） | — | ✗ | ✓（存储） | 校验用 |
| witness / π | 副本 | 副本 | 生成 | 可选 | ✓（Verify） |

**说明**：

- 「✗」表示架构契约**禁止**该角色在数据面获得对应明文或未授权完整态。
- 托管服务器**默认**不导出明文；仅作为 `inference_peer` 时在受控会话内处理非线性。

### 3.2 无头密态推理服务 · 密文专属契约

| 维度 | 隐私含义 |
|------|----------|
| **数据面** | 仅密文载荷、密文句柄、绑定元数据、公开参数、证明工件 |
| **禁止面** | 不接收、不缓存、不持久化用户明文输入、明文激活、解密私钥 |
| **非线性** | 明文算子仅存在于推理交互方；无头服务经 `TruncateRequest` / 回注闭合环 |
| **MPC 扩展** | 秘密分片面；单方仍不得未授权还原完整输入或权重（§6.3） |

## 4. 五类隐私机制保证

各模态族共享下列机制（与具体 CNN 拓扑 / LLM 规模无关）：

### 4.1 输入域隔离（Input Boundary）

- 预处理与定点化驻留**客户端可信域**。
- 无头服务 **P2 仅收输入承诺**（SHA-256 / `cm_x`）；数据面**仅收密文输入句柄**。
- 不开放用户明文载荷入站 API（密文专属契约）。

### 4.2 密态–明文协作环（Hybrid Compute Loop）

- 同态兼容的**线性算子**在无头服务**密态域**执行。
- **非线性**在用户指定的 `inference_peer`（`client_local` | `custody_host`）**明文域**完成后，密文**回注**会话。
- P3 为**多次双端交互协作**；交互位置由用户指定，不必与验证对象相同。

### 4.3 传输域隔离（Transport Segregation）

| 链路 | 要求 |
|------|------|
| 客户端 ↔ 托管 | **HTTPS** TLS 1.2+（OVDS 读写） |
| 客户端 ↔ 无头推理 | **HTTPS** 控制面 + **WSS** 数据面 |
| 无头推理 ↔ 托管 | HTTPS / mTLS（绑定复核、代行 P3） |

控制面 REST **仅**承载元数据与承诺；密文 / 分片走独立数据面信道。**禁止**生产环境明文 HTTP。

### 4.4 会话域隔离（Session Isolation）

- 推理状态按**会话 ID** 隔离。
- 批处理下各样本独立密态环与 `phase_id`，互不串扰。
- 优化器并发仅在配额内并行，不合并跨用户会话密钥（`execution_trust` 门禁）。

### 4.5 输入承诺绑定（Commitment Binding）

- P2 提交密码学输入承诺。
- 无头服务**不持久化**用户明文态数据。
- `data_digest`（OVDS）与 `cm_x`（P2）一致性由平面四**双验证器**在 P6 核验；客户端可 **`client_reverify`**。

## 5. 传输与接入层隐私

TLS 与身份认证**分层**，共同构成传输隐私：

| 层 | 机制 | 隐私作用 |
|----|------|----------|
| **TLS** | 链路加密、证书校验 | 防窃听与中间人 |
| **JWT / OIDC** | 调用者身份 | 防未授权访问 |
| **ACL / RBAC** | 资源授权 | 防跨租户 / 跨文件读取 |
| **VADS 验签** | 分片密码学合法 | 防块替换（完整性，支撑隐私链） |

托管写入路径：`JWT 通过 → ACL 写权限 → KMS 代签 → VADS Append`；`owner_id = JWT.sub` 写入 manifest。

## 6. 按模态族与体制的隐私特征

### 6.1 CNN 族（E₂ ElGamal · `strict_proof`）

| 项 | 说明 |
|----|------|
| 明文域 | 客户端或 `inference_peer`：ReLU、定点 shift |
| 无头服务见 | 密文线性层；P2 摘要；公开权重 |
| 完整性 | CP-SNARK 不扩大明文面；γ 非交互本地派生 |
| 参考实例 | SimpleCNN / MNIST：见顶层架构附录 A.3 |

### 6.2 LLM 族 · 混合 HE（`game_sampling`）

| 项 | 说明 |
|----|------|
| 非线性 | 计算图线性化、激活近似；明文域最小化但仍存在于交互方 |
| 无头服务见 | 密文线性子图、分层承诺元数据 |
| 完整性 | 抽样审计；可与验证对象交互挑战 |
| 与 CNN 差异 | 不构建全电路 CP-SNARK；隐私—性能权衡更依赖用户 `PrivacyModePreference` |

### 6.3 LLM / 多模态 · MPC（`mpc_puma` · *待扩展*）

| 项 | 说明 |
|----|------|
| 数据面 | **秘密分片**交换，非 HE 密文句柄 |
| 参与方 | 客户端 / 托管 / 无头服务按 PUMA 类拓扑映射（§4.3.2） |
| 门禁 | **`ComputeParityGate`**：算力对等 + 托管场景下**非合谋**假设 |
| 隐私强度 | 依赖 MPC 协议安全；平台附加 `mpc_protocol` transcript 审计 |
| 完整性 | 不调用 `CPS.Ver`；`mpc_trace` + 双验证器 |

**算力对等条件**（MPC 进入候选集的前提）：

| 模式 | 条件 |
|------|------|
| `client_local` | 客户端与无头推理服务算力对等 |
| `hosted` | 托管与无头推理服务算力对等，且用户信任托管、**MPC 层不合谋** |

## 7. 数据托管双模式与隐私

| 模式 | 数据存放 | 隐私特征 | 典型用户 |
|------|----------|----------|----------|
| **`hosted`** | 信任托管 VADS/OVDS | 客户端薄；非线性 / 验证可卸载；依赖托管方信任与 TLS | 边缘低算力 |
| **`client_local`** | 用户设备 | 明文与密钥尽量本地；无 OVDS 块或仅摘要上链 | 高算力工作站 |

两种模式均须保证：**入库 → 绑定 → 推理 → 验证** 链路不断裂（见 [数据流图](./vpin-平台数据流图.md)）。

`DeploymentRecommendation`（边缘 / 拒绝检测）默认推荐 `hosted` + `custody_host`，降低本地明文算子负载，但**增加对托管方的信任依赖**——用户可覆盖并确认。

## 8. 用户可控隐私杠杆

用户通过下列配置表达隐私—性能倾向（不改变六平面边界）：

### 8.1 `PrivacyModePreference`（密态隐私模式）

| 模式 | 倾向 |
|------|------|
| `strict` | 高安全：严格证明、最小明文域；接受更高通信与密态加载成本 |
| `balanced` | 默认均衡 |
| `performance` | 低延迟、浅协作环、托管 offload |
| `bandwidth` | 少 P3 往返、小密文载荷 |
| `custom` | 自设通信 / 推理 / 密态加载 / 安全四维权重 |

`preferred_scheme_id` 可显式选用注册表内体制（须在可行域内）；**不改变**密文专属契约。

### 8.2 `DataBindingRecord` 终端指定

| 字段 | 隐私影响 |
|------|----------|
| `inference_peer` | 决定 P3 明文非线性在**本机**还是**托管**执行 |
| `verifier_target` | 决定 P6 验证在**本机**还是**托管**执行 |
| `custody_mode` | 决定用户数据块是否离端 |

### 8.3 设备检测与 `execution_trust`

| 等级 | 隐私相关约束 |
|------|--------------|
| `trusted` | 允许全量优化（含批内密钥复用等） |
| `constrained` | 禁止 `batch_key_reuse`；限制远端卸载 |
| `untrusted` | **阻断**密态推理与托管写入 |

用户可**拒绝设备检测**：采用 `FallbackBaselineProfile`，`execution_trust` 固定 `constrained`，不可伪造为高信任。

## 9. 工程优化器与隐私边界

工程优化器（`InferenceOptimizer`、`CustodyOptimizer`）**不改变密码语义**，但影响**性能与落点**：

| 优化器 | 隐私相关行为 |
|--------|--------------|
| `InferenceOptimizer` | 调度并发、流水线、`offload_policy`；不扩大 `server_visible` 明文集 |
| `CustodyOptimizer` | 并行 OVDS 写入 / 拉取验证；均在 **HTTPS TLS** 上执行 |
| `StartupOptimizer` | 边缘推荐托管交付；用户可覆盖 |

优化器输出不得绕过 `execution_trust` 硬门禁或密文专属契约。

## 10. 隐私与完整性的协作

| 平面 | 命题 | 输出 |
|------|------|------|
| **平面三 隐私** | 数据与流程是否按契约保密、隔离 | 机制设计（本文） |
| **平面四 完整性** | 绑定与推理是否未被篡改、证明是否成立 | `privacy_integrity`、`inference_integrity` |

双验证器顺序：

1. **模型推理验证器**：CP-SNARK Ver / 博弈抽样 Verify / MPC transcript 审计 → `inference_verdict`
2. **密态流程验证器**：OVDS `verify` + `ahe_trace`/`mpc_trace` 审计 + **收录** `inference_verdict` → `privacy_integrity`

`inference_integrity = fail` 时，`privacy_integrity` **不得**单独判 `pass`。

客户端**本地复核**（`client_reverify`）提供对托管方结论的二次隐私—完整性保障，不重跑 P3 推理。

## 11. 平台隐私边界声明（架构级）

下列内容属于**架构应然**，非渗透测试结论：

**平台设计保障（在合规实现前提下）**：

- 无头推理服务无用户明文 I/O 通道（HE）；MPC 下单方不可未授权还原完整态（*待扩展*）。
- 托管数据经 ACL + TLS；推理链路独立 TLS。
- 输入承诺与 OVDS 绑定可验证；客户端可复核。

**不在本文承诺范围**：

- 推理交互方或托管方**恶意**时的一切侧信道与物理攻击；
- 用户主动将明文上传至非契约 API；
- MPC / HE 底层密码学假设被破坏；
- 生产 TLS 配置错误、证书泄露、IdP 沦陷等运维事故。
