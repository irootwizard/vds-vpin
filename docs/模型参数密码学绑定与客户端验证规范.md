### 0.2 模型与输入（两套向量，勿混）

| 符号 | 维度 / 取值 | 含义 | 与代码 |
|------|-------------|------|--------|
| **$\mathbf{W}^*$** | $N_W \approx 1219$（network A） | 客户端认定的**完整静态 CNN 参数**（卷积核 + FC 权重 + bias），按 manifest 顺序 flatten | `Pre_trained_model/*.npy` |
| **$N_W$** | 标量 | $\mathbf{W}^*$ 的向量长度（network A 为 1219）；**不是**点乘次数 $J$ | §六 network A 表 |
| **$\mathbf{w}$** | 长度 $N_{\mathrm{cm}}$ | **被 $\mathrm{Com}$ 承诺的标量向量**；理想态 $N_{\mathrm{cm}} = N_W$，当前实现 $N_{\mathrm{cm}} = 178$ | `commit_model(weights)` 的输入 |
| **$w_i$** | $i = 0,\ldots,N_{\mathrm{cm}}-1$ | $\mathbf{w}$ 的第 $i$ 个分量（嵌入 $\mathbb{Z}_{q_1}$ 后） | `embed_u128_to_scalar` |
| **$x$** | 依输入规模 | 推理输入（定点明文或密文编码后的向量） | 客户端图像等；**不是**曲线系数 $a$ |
| **$\mathcal{G}$** | — | 网络**拓扑**（层类型、顺序、shape、截断计划） | manifest + `topology_hash` |
| **$\tau$** | 固定长度哈希 | $H(\mathcal{G}, \texttt{manifest}, \mathsf{cm}_{\mathbf{W}})$，绑拓扑与模型 ID | 目标字段 `topology_hash` |

**易错点：** $\mathbf{W}^*$（1219 维静态模型）$\neq$ $\mathbf{w}$（当前承诺的 178 维轨迹标量）$\neq$ witness 全文（数十万维 R1CS 赋值）。

### 0.3 承诺与打开

| 符号 | 含义 | 代码 |
|------|------|------|
| **$\mathsf{cm}_{\mathbf{W}}$** | 模型承诺（协议对象） | `ModelCommitmentBundle`，含 `cm_weights` |
| **$\mathsf{cm}_x$** | 输入承诺 | `InputCommitmentBundle` |
| **$C_W$** | 链外 Pedersen 承诺点（群元素） | `cm_weights.point_hex` 解压后 |
| **$R_W$** | Merkle 根（替代或补充 Pedersen） | L1′ 方案，**目标** |
| **$\mathrm{Com}(\cdot)$** | 承诺算法 | 现 `commit_model` / `commit_public_inputs` |
| **$r$** | Pedersen 盲化标量 | `commit_model` 返回值，**未**写入 `protocol.json`（缺口） |
| **$H(i)$** | 第 $i$ 个承诺分量的生成元标量 | `SHA256(b"cp-snark-model-gen" ++ le64(i))` → `Scalar` |
| **$G$** | Ristretto255 基点 | `RISTRETTO_BASEPOINT_POINT` |
| **$\mathrm{VerifyOpen}$** | 验证 $C_W = rG + \sum_i H(i)\, w_i G$ | **目标**；现仅 `digest_hex` |

Pedersen 展开（与 `commitment.rs` 一致）：

$$
C_W = r \cdot G + \sum_{i=0}^{N_{\mathrm{cm}}-1} H(i) \cdot w_i \cdot G
$$

| 符号 | 取值（network A） | 含义 | 代码 |

1. **不要在反引号行内代码里写 LaTeX**（如 `` `vars_para[\mathrm{slot}(j)]` ``）：预览器会当纯文本显示 `\mathrm`，且 `[...](j)` 易被误判为**链接**。

## 1. 安全目标（Ideal 功能）

### 1.1 参与方

| 角色 | 持有 | 协议动作 |
|------|------|----------|
| **服务器 P** | 模型 $\mathbf{W}$、同态推理实现 | Setup 发 $\mathsf{cm}_{\mathbf{W}}$；推理；生成 $\pi$ |
| **客户端 V** | 选定 `model_id`、输入 $x$、公开参数 | 接受 $\mathsf{cm}_{\mathbf{W}}$；采样 $\gamma$；**仅**根据 $\mathsf{cm}$、$\pi$、$\gamma$ 验证 |

### 1.2 要证的关系（论文级，简化）

$$
\exists\, \mathbf{W}, x:\;
\mathsf{cm}_{\mathbf{W}} = \mathrm{Com}(\mathbf{W}^*) \;\wedge\;
\mathsf{cm}_x \text{ 绑定 } x \;\wedge\;
\mathsf{NN}_{\mathcal{G}}(\mathbf{W}, x) \text{ 的 AHE/EC 实现正确}
$$

其中：

- $\mathbf{W}^*$、$N_W$：见 §0.2；
- $\mathcal{G}$、$\tau$：见 §0.2、§0.3。

### 1.3 当前仓库实际接近的命题

$$
\exists\, \text{轨迹 } T:\;
R_{\mathrm{PtAdd}}(T) \land R_{\mathrm{PtMul}}(T) = 1
$$

- $T$ 含 $J=178$ 次 PtMul、$A=2144$ 次 PtAdd（network A，§0.8）；
- `weight.json` 长度 $N_{\mathrm{cm}}=J$：每个 $w_i$ 是轨迹乘数，**不是** $\mathbf{W}^*$ 的 $N_W$ 维展开（见 `CP-SNARK自检` §4.2(1)）；
- **无** R1CS 将 $\mathbf{W}^*$ 与 $a_j$ 代数连接。

**结论：** 仅做链外 $\mathsf{cm}_W$（哪怕扩到 1219 维）+ 现有 PtMul SNARK，**不能** 证「使用了指定模型的卷积核与网络权重计算」。

## 2. 为何「承诺 + EC-SNARK」在密码学上不够

记：

- $C_W = \mathrm{Com}(\mathbf{w})$：链外 Pedersen（§0.3）或 Merkle 根 $R_W$；
- $\pi_{\mathrm{ec}}$：Spartan 对 $R_{\mathrm{PtAdd}}$、$R_{\mathrm{PtMul}}$ 的 SNARK（§0.5）；
- $\mathbf{a} = (a_0,\ldots,a_{J-1})$：$J$ 次 PtMul 乘数（§0.4），与 $\mathbf{w}$ 维数 $N_{\mathrm{cm}}$ 在现实现中相等均为 178，但语义不同（§0.2）。

若无关系 $R_{\mathrm{bind}}$（MAC 层），下列在知识 soundness 意义下仍可能：

1. P 对 $\mathbf{W}^*$ 做正确 $C_W$，但用 **另一组** $\mathbf{a}'$ 通过 $R_{\mathrm{PtMul}}$；
2. $\mathbf{a}$ 来自 `pf(secret_key,i)` 等 **RLC 演示系数**，与卷积核无代数关系（`cnn_networks/Server.py` `rLCR`）；
3. V 从 `rust_files/.../weight.json` 重算 digest（`protocol.rs` `verifier_run`），则 V **不是** 仅持 $\mathsf{cm}$ 的独立验证者。

**模型绑定需要三元组同时在协议中出现：**

```text
  cm_W  ←——→  MAC / 网络语义 (W*, x)  ←——→  π_ec
```

中间 **MAC/网络语义** 是当前缺失的核心密码学环节；见 §4 层 2。

## 3. 三套「承诺」勿混（术语）

| 对象 | 个数/形式 | 语义 |
|------|-----------|------|
| **链外** `cm_weights.point_hex` | **1** 个 Ristretto 点 | 对 **向量** $\mathbf{w}$ 的 Pedersen：$C_W = rG + \sum_i H(i) w_i G$ |
| **链内** `comm_vars_para` | 1 组多项式承诺 | 对 **整条** `vars_para` witness 向量的 Spartan PC，非 Setup 的 $\mathsf{cm}_W$ |
| **R1CS 乘数槽** | 每 $j$ **1** 个标量 | 乘数 $a_j$ 在 `vars_para` 中的下标 $\mathrm{slot}(j)$，见下式 |

**$J=178$ 个 $j$** = 178 次 **PtMul 运算索引**，不是 178 个卷积核；$N_W \approx 1219$ 与 $J$ **无数相等关系**（§0.8）。

乘数槽下标（与 `point_mult.rs` 中 `n + one_num_vars * j` 一致，$n$ 即 $n_{\mathrm{bit}}$）：

$$
\mathrm{slot}(j) = n_{\mathrm{bit}} + j \cdot V_{\mathrm{blk}}, \quad n_{\mathrm{bit}}=128,\; V_{\mathrm{blk}}=3466
$$

## 4. 密码学绑定：五层架构

```text
Setup:     V 接受  cm_W = Com(W*) ,  topology_hash τ
Input:     V 与 P 固定  cm_x 绑定 x
Challenge: V 采样  γ, γ'  （论文式 (9)(10)）
Prove:     P 输出  π = (π_MAC , π_ec , openings, …)
Verify:    V 检查  Open(cm_W) + Verify(π) + γ 在 transcript 中
```

### 层 0 — 静态参数集合（Setup）

**机制：**

$$
\mathsf{cm}_{\mathbf{W}} = \mathrm{Com}(\mathbf{W}^*; r), \qquad
\tau = H(\mathcal{G}, \texttt{manifest}, \mathsf{cm}_{\mathbf{W}})
$$

- $\mathrm{Com}$：Pedersen 向量承诺（现 `commit_model`）或 Merkle 根 $R_W$；
- manifest：flatten `.npy` 的**固定顺序**、层名、shape；
- $\tau$：防同参不同拓扑、防换 `model_id` 不换 cm。

**V（Setup）验证：**

1. 从 catalog 读取 $(\mathsf{cm}_{\mathbf{W}}, \tau, \texttt{manifest})$；
2. 首次注册可验 $\mathrm{Com}(\mathbf{W}^*)$ 与 manifest 一致；
3. 持久化 `model_id → (cm_W, τ)`，会话中 **拒绝** 与目录不符的 $\mathsf{cm}$。

**保证：** 之后会话声称的模型 ID 与 **同一** 承诺值绑定。  
**不保证：** 推理使用了这些参数。

**链外计算量：** $O(|W|)$ 次群标量乘（1219 量级仍 **毫秒级**）；对 Spartan prove **≈0%** 增幅。

---

### 层 1 — 打开绑定（Prove）

**机制：** P 提供 opening $(\mathbf{W}, r)$ 或 NIZK $\pi_{\mathrm{open}}$：

$$
\mathrm{VerifyOpen}(C_W, \mathbf{W}, r) = 1
$$

**V 验证：**

3. 重算 $C_W$ 与 `point_hex` 一致（`decompress_commitment` + 累加，现 **未实现**）；
4. 可选：`digest_hex` 与 $\mathrm{SHA256}(\mathrm{concat}_i(\mathrm{bytes}(w_i)))$ 一致（**不能** 替代 3）。

**保证：** P 不能在不明示 $\mathbf{W}$ 下声称与 $C_W$ 一致。  
**不保证：** $\mathbf{W}$ 进入本次 MAC/推理。

**工程缺口（P1a）：** `blind` 未写入 `protocol.json`；`verify_model_commitment` 仅比 digest（审查报告 §三.1）。

---

### 层 2 — MAC → 轨迹乘数（核心，L2）

将 CNN 每层 MAC 写成 $R_{\mathrm{MAC}}$：

- 卷积：论文式 (6) 精神 — 窗口乘加；
- FC：式 (8)；压缩：式 (10) 与 $\gamma'$；
- 验证方随机线性组合：式 (9) 与 **客户端** $\gamma$。

**连接子电路（对每个轨迹索引 $j$）：**

$$
a_j \cdot 1 = \mathrm{OutMAC}_j(\mathbf{W}, x, \gamma, \gamma')
$$

其中 $a_j$ 为 witness 向量 `vars_para` 在 $\mathrm{slot}(j)$ 处的分量。Rust 代码为 `vars_para[n_bit + j * one_num_vars]`（`point_mult.rs`，此处 `n_bit` 即符号 $n_{\mathrm{bit}}$）。$\mathrm{slot}(j)$ 的定义见 **§3** 独立公式块。$\mathrm{OutMAC}_j$ 见 **§0.6**。

**做法 A — 显式 MAC 电路：** 每层 MAC 代数正确，再 L1 钉到 PtMul。

**做法 B — RLC 压缩（论文）：** V 先采样 $\gamma$，transcript 绑定 $(\mathsf{cm}_W, \mathsf{cm}_x, \gamma)$，P 证压缩 MAC 与 EC 轨迹一致。

**V 验证：**

5. transcript 含 $\mathsf{cm}_W, \mathsf{cm}_x, \gamma$ 且顺序固定；
6. $\gamma$ 与 V 本地采样一致（**禁止** 生产路径用 `pf(secret_key)`）；
7. $\mathrm{SNARK.Verify}(\pi_{\mathrm{MAC}})$（若独立电路）；
8. $\mathrm{SNARK.Verify}(\pi_{\mathrm{ec}})$ + $\forall j:\, a_j = \mathrm{OutMAC}_j$。

**保证（在 Com 绑定 + SNARK knowledge soundness + ROM/FS 下）：**  
MAC 输入来自 $\mathbf{W}^*, x$，且 PtMul 乘数等于 MAC 输出 → **指定卷积核/FC 参与计算**（在 MAC 被电路覆盖的范围内）。

**计算量（network A，见 `CP-SNARK自检` §7.4、§八）：**

| 变体 | 约束倍率 | prove 粗估 |
|------|----------|------------|
| 式 (10) 压缩 L2 | **≈1.16×** | ~230–270 s |
| FC naive | **≈7.6×** | ~25–35 min |
| 卷积进电路或式 (9) | 另计 | 需单独 benchmark |

### 层 3 — 静态 $\mathbf{W}$ 进入 MAC

MAC 中每个权重 $w_i$ 必须与 $\mathbf{W}^*$ 一致：

| 方式 | 说明 |
|------|------|
| **L1 等式** | 公开 $w_i^{\mathrm{pub}}$；R1CS：$w_i^{\mathrm{pub}} \cdot 1 = w_i^{\mathrm{MAC}}$ |
| **Merkle 打开（L1′）** | $R_W = \mathrm{Merkle}(\mathbf{W}^*)$；每次用 $w_i$ 验 $\log|W|$ 路径 |
| **Pedersen 进 R1CS** | 电路内重算 Com（贵，一般不采用） |

**V：** 对每个 `UsedIndices` 验 Merkle 路径，或验公开输入与 opening 一致。

**计算量（L1′，仅 178 次访问）：** $\Delta C \approx 178 \times \log_2(1219) \times c_h \approx 3560\text{–}53400$（$c_h$ 依哈希 gadget），相对 638k 约 **+0.6%–+8%**。

**外推到 $|W| \gtrsim 10^6$：** 公式不变，但须用 **Merkle 根作 Setup 主承诺**、Prove 仅打开 `UsedIndices`（规模 $k_w$）；禁止全量 L1 等式与 R1CS 内全量 Pedersen。数量级与工程清单见 [`大模型模型承诺优化方案.md`](./大模型模型承诺优化方案.md) §5–§7。

**电路内哈希：** 须 **Poseidon**（$\mathbb{F}_{q_1}$），禁止 SHA256 全路径进 R1CS。见 [`完整密码学交互与模型绑定-数学过程与复杂度.md`](./完整密码学交互与模型绑定-数学过程与复杂度.md) §7.0。

**防伪造与 P4′：** UsedIndices 硬绑定（T1）+ 可选客户端随机 $\mathcal{S}_{\mathrm{ch}}$ 审计（T3）；不能保证「换模型 CPU > Setup」，能保证伪造 $\mathrm{negl}(\lambda)$。见专文 §7.7。

### 层 4 — 输入 $x$ 与拓扑 $\mathcal{G}$

- $\mathsf{cm}_x = \mathrm{Com}(x)$ 或密文承诺；MAC 与 $\pi_{\mathrm{ec}}$ 使用 **同一** $x$（现 `cm_x` 仅曲线系数 $a$，不足）；
- $\tau$ 写入 transcript / 公开输入，绑层维度、截断计划。

### 层 5 — AHE 密文链（L3，完整 vPIN）

## 6. 客户端验证算法（规范）

**硬性要求：** 不得依赖 `rust_files/{network}/pointMult/weight.json` 或服务器本地权重路径（平台架构 §2.2、路线图 R4 / 审查 P1b）。

### 6.1 Setup

```text
Setup(model_id):
  从 catalog 读取 (manifest, W*, cm_W, topology_hash τ)
  若带签名注册：验签 manifest 与 cm_W
  持久化 (model_id → cm_W, τ)
```

### 6.2 会话与挑战

```text
SessionStart(x):
  cm_x ← Com(x) 或本地 x 与服务器提交的 cm_x 比对
  γ, γ' ← FS-RNG( prefix = cm_W || cm_x || session_id )
  发送 Challenge{ γ, γ', cm_x } → 服务器（TLS 内）
  禁止服务器代采 γ 作为生产路径
```

### 6.3 Verify

```text
Verify(session, π):
  // 1) 承诺与目录
  assert π.cm_W == stored.cm_W
  assert π.τ == stored.τ

  // 2) 打开（P1a）
  assert VerifyOpen(π.cm_W, π.W_open, π.r_open)

  // 3) 输入（P2，闭合后）
  assert VerifyOpen(π.cm_x, π.x_open, …)  // 或 V 本地 x 派生

  // 4) 挑战绑定
  assert TranscriptContains(π, cm_W, cm_x, γ) in fixed order
  assert π.γ == local.γ

  // 5) 按层子证明（见设计定稿 §5；勿用合并 mac_rlc 桩）
  assert SNARK.Verify(π_conv, …)   // 式 (9)，公开输入含 γ
  assert SNARK.Verify(π_pool, …)   // 式 (7)
  assert SNARK.Verify(π_fc*, …)  // 式 (10)，公开输入含 γ′
  assert SNARK.Verify(π_ec_*, …) // 各层 EC gadget
  // 客户端不逐格验 eq5/eq8（γ 下 eq9/eq10 足够）
  assert ∀j: OutMAC_j == a_j      // L1 连接（承诺闭合后）

  // 6) Merkle（若 L1′）
  assert ∀i ∈ UsedIndices: MerkleVerify(R_W, W_i, path_i)

  return accept
```

**任一失败 → reject**；不得 fallback 到读 `weight.json`。

### 6.4 Accept 的密码学含义（应对外表述）

> 在目录中的 $\mathsf{cm}_{\mathbf{W}^*}$、会话 $\mathsf{cm}_x$ 绑定的输入、拓扑 $\tau$、客户端 $\gamma$ 下，**MAC 关系**与 **EC 轨迹（PtAdd/PtMul）**一致，且轨迹乘数与 MAC 输出一致。

**不是：**「digest 与服务器 JSON 相同」或「仅 EC gadget 自检通过」。

## 7. Soundness 草图

**假设：** $\mathrm{Com}$ 在 DL 下绑定；各层 $\pi_{\mathrm{conv}}/\pi_{\mathrm{pool}}/\pi_{\mathrm{fc}}$ 与 $\pi_{\mathrm{ec}}$ 在 ROM+FS 下 knowledge sound；**客户端** $\gamma,\gamma'$ 在 transcript 中 **先于** prove。

**则：** 若 V accept，存在 opened $\mathbf{W}$ 使：

1. $\mathbf{W}$ 与 V 存盘的 $\mathsf{cm}_{\mathbf{W}}$ 一致；
2. MAC 在 $(\mathbf{W}, x)$ 下成立（$\pi_{\mathrm{MAC}}$）；
3. 每个 $a_j$ 等于对应 MAC 输出（L1/连接约束）；
4. EC gadget 正确（$\pi_{\mathrm{ec}}$）。

卷积核：若卷积 MAC 约束中的系数 **即** $\mathbf{W}^*_{\mathrm{conv}}$ 的 Merkle 叶子或 L1 公开分量，则「指定卷积核参与」为 (2)(3) 的推论。
