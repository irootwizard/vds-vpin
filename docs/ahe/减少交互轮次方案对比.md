# 减少 AHE 交互轮次——方案对比与选型

> **背景**：本项目使用 ECC 指数 ElGamal 加性同态加密。客户端交互由两个独立条件触发：
> - **ReLU**：非线性，必须客户端解密后执行
> - **Scale 截断（shift）**：每层浮点权重（f=16）使 scale +16 bit，超出 BSGS 解密上限（10¹³ ≈ 2⁴³）前必须截断，且 ECC ElGamal 中整数除法只能由客户端完成
>
> 这两个触发器相互独立——去掉 ReLU 但保留 shift，交互轮次不减。这是与 CKKS/FHE 的根本区别：CKKS 的 bootstrapping（等价于 shift）在**服务端**完成，而 ECC ElGamal 的 shift 在**客户端**。

---

## 当前基准

| 模型 | 当前轮次 | 优化下限（架构约束） |
|------|---------|------------------|
| new_lenet_mnist | 4 | 4（每层都需 shift） |
| new_lenet | 4 | 4 |
| new_resnet | 18 | 受方案决定 |

## 方案一：Catalog 思路（❌ 不适用）

**来源**：新增功能/catalog.md；文献 *Half the Nonlinearity Is Wasted*（arXiv:2603.03459）

**思路**：统计各层非线性重要性，将中间层 ReLU 替换为恒等，减少 Linear/Nonlinear 切换次数。

**为何不适用**：

Catalog 的核心收益依赖 CKKS/FHE 中 bootstrapping 在服务端完成。在 ECC ElGamal 中：
- 跳过 relu → 仍需 shift（scale 仍然增长）→ 仍需客户端交互
- 一次交互 = relu + shift，去掉 relu 并不减少交互次数
- 该方案在 Transformer（MLP 层数多、中间层冗余大）中效果显著；CNN 层数少、每层更关键，收益进一步打折

**结论**：在当前 ECC ElGamal 框架下，Catalog 方案**无法减少交互轮次**，仅能略微减少客户端每次交互的计算量（少做一次 relu）。

## 方案二：重训方案（⚠️ 需重训，效果最好）

**来源**：DeepReDuce（ICML 2021，arXiv:2103.01396）；CryptoNAS

**思路**：分析各层 ReLU 对精度的贡献，选择性删除贡献低的 ReLU 并微调恢复精度，同时降低权重精度（f=8 替代 f=16）以减缓 scale 增长。

### 2.1 仅减少 ReLU（不改权重精度）

对 new_resnet 每个 BasicBlock 去掉 conv1 后的 ReLU：

```
原结构（每 block 2 轮）：
  conv1 → [client: relu+shift] → conv2 → [client: relu+shift]

去 ReLU 后（每 block 仍需 2 轮，因 shift 不变）：
  conv1 → [client: shift only] → conv2 → [client: shift only]
```

**结论**：轮次不减，只是每次客户端不做 relu。**无效**。

### 2.2 降低权重精度 + 减少 ReLU（双管齐下）

将权重量化到 f=8（INT8 量化感知训练），scale 增长减缓：

```
conv(f=16_input, f=8_weight) → 输出 f=24
再一层 conv(f=24_input, f=8_weight) → 输出 f=32
```

两层才需一次截断，每 block 的 2 个 conv 可合并为 1 次客户端交互：

```
conv1(f=8 weight) → conv2(f=8 weight，服务端连续) → [client: relu+shift]
```

同时去掉 conv1 后 ReLU，则每 block 只需 **1 次交互**（而非 2 次）。

**预期效果**：new_resnet 18 轮 → **约 9 轮**

**代价**：INT8 量化感知训练（需重训），精度损失取决于量化质量，通常 <1%。

## 方案三：替换 CKKS 方案（⚠️ 需换密码体制，效果最好）

**来源**：AESPA（arXiv:2201.06699）；BootNet（eprint 2026/1279）；CKKS 多项式近似系列

**思路**：将 ECC ElGamal 替换为 CKKS 全同态加密。CKKS 中 bootstrapping（等价于 shift）在**服务端**完成，ReLU 可用多项式近似在服务端计算，客户端无需参与任何中间层。

### 交互模式对比

| | ECC ElGamal（当前） | CKKS 替换后 |
|--|-------------------|------------|
| 线性层（conv/FC） | 服务端 | 服务端 |
| Scale 截断 | **客户端**（每层） | 服务端 bootstrapping |
| ReLU | **客户端** | 服务端（多项式近似） |
| 最终解密 | 客户端 | 客户端 |
| 交互轮次 | 18（ResNet） | **1**（只有最终解密） |

### 精度与代价

- 多项式近似 ReLU 引入约 0.3–1% 精度损失（AESPA 二次近似，CIFAR-10/ResNet）
- CKKS bootstrapping 计算成本高：ResNet18 一次推理约需数十秒至数分钟（无 GPU 加速时）
- **失去 CP-SNARK 兼容性**：现有 vPIN 的可验证性框架基于 ECC 曲线构建，切换 CKKS 需重新设计可验证协议
- BootNet（eprint 2026/1279）通过将 conv + relu + bootstrapping 融合进单次 bootstrapping 调用，是目前 CKKS+ResNet 推理效率最高的方案

**结论**：交互轮次降至 1，但代价是放弃 ECC ElGamal 及现有 CP-SNARK 框架，属于**系统级重构**，不是短期选项。

## 方案四：Block 线性化方案（✅ 不重训，有望降低轮次）

**来源**：ReplaceMe（arXiv:2505.02819）；FlattenGPT（arXiv:2602.08858）

**思路**：用少量校准数据（无需标签，仅前向推理）拟合线性矩阵 $A$，将多个连续 Block 替换为单次矩阵乘法：

$$A \approx \text{Block}_{i+1}(\text{Block}_i(x)), \quad A = \arg\min_A \|A X - Y\|_F$$

其中 $X, Y$ 为校准集上的输入/输出特征。

### 对 ResNet18 的具体应用

ResNet 中 identity shortcut block（layer1/layer2 中 stride=1 的部分）线性化潜力最高：

```
原来 2 个 identity block（4 轮）：
  Block_i → [client: relu+shift] → Block_{i+1} → [client: relu+shift]

线性化后（1 轮）：
  MatMul(A, x) → [client: shift only（或 relu+shift 视近似质量）]
```

**预期效果**：若 layer1 的 2 个 block、layer2/3/4 各 1 个 identity block 可线性化，ResNet18 轮次约从 18 降至 **10–12 轮**（待实验验证）。

### 线性化误差与适用性

| Block 类型 | 线性化潜力 | 原因 |
|------------|----------|------|
| Layer1 identity block（64→64，stride=1） | ★★★★ | shortcut 恒等，主路径宽，近线性 |
| Layer2/3/4 第二个 block（identity shortcut） | ★★★ | 类似 layer1 |
| Layer2/3/4 第一个 block（downsample shortcut） | ★★ | stride=2+通道变化，非线性较强 |
| 最后几层 block（layer4） | ★★ | 学到高级特征，非线性更重要 |

### 实施步骤

```
Step 1  准备校准集（100–500 张图，无需标签）
Step 2  对目标 block 对，记录输入 X 和输出 Y
Step 3  求解 A = Y @ pinv(X)（最小二乘，离线完成）
Step 4  验证近似误差：‖AX - Y‖ / ‖Y‖ < threshold（建议 5%）
Step 5  将 A 量化到 f=16，注册为服务端同态矩阵乘
Step 6  测试端到端精度，接受则部署，否则放弃该 block 对的线性化
```

**优点**：无需重训，仅需推理时校准；失败可回退
**缺点**：精度损失不可预知，需实验；线性近似对复杂特征学习的 block 效果差

## 综合对比

| 方案 | 是否重训 | 是否换密码体制 | ResNet 预期轮次 | 精度损失 | 可行性 |
|------|---------|--------------|--------------|---------|-------|
| Catalog（跳 relu） | 否 | 否 | 18（不变） | 极小 | ❌ 无效 |
| 重训（去 relu，f=8） | **是** | 否 | **约 9** | <1% | ✅ 推荐长期 |
| 替换 CKKS | 是/否 | **是** | **1** | ~0.5% | ⚠️ 系统重构 |
| **Block 线性化** | **否** | 否 | **约 10–12** | 待测 | ✅ 推荐短期探索 |

---

## 建议路线

```
短期（当前已训练模型）
  → 尝试 Block 线性化（方案四）
  → 从 layer1 identity block 对开始，验证近似误差和精度损失
  → 若精度可接受：ResNet 18 轮 → 约 10 轮

中期（允许少量重训）
  → INT8 量化感知训练 + 去除 block 内中间 ReLU（方案二）
  → ResNet 18 轮 → 约 9 轮，精度损失可控

长期（系统扩展至 LLM）
  → 按 catalog §9 研究路线，切换 CKKS，针对 500M Transformer 构建新推理系统
  → 参考 BootNet 的 conv+relu+bootstrapping 融合策略
```
