#### 1.4.1 三套向量（禁止混称）

| 符号 | network A | 含义 | 代码 |
|------|-----------|------|------|
| **$\mathbf{W}^*$** | $N_W = 1219$ | 完整静态 CNN 参数（conv + FC + bias） | `full_weights.json`、`load_w_star` |
| **$\mathbf{w}$** | 目标 $N_{\mathrm{cm}} = N_W$ | Setup 被 $\mathrm{Com}$ 承诺的标量向量 | `commit_model(load_w_star)` |
| **轨迹乘数 $a_j$** | $J = 178$ | 第 $j$ 次 PtMul 的 witness 乘数槽标量 | `vars_para[slot(j)]`，`weight_list[j]` |

$\mathbf{W}^* \neq$ 178 维 `weight.json`（旧轨迹 MAC 系数）$\neq$ 全 R1CS witness（$\sim 6.5\times 10^5$ 维）。

#### 1.4.2 $\mathsf{cm}_W$：论文 **B′** vs 本仓 Pedersen（过渡）

**论文（network A 定案）：**

$$
\hat{\mathsf{cm}} \leftarrow \texttt{CPS.Comm}(\mathbf{W}^*, r, pp') \quad\text{（Spartan/Hyrax PC，附录 Fig.6）}
$$

验证：$\texttt{CPS.Ver}(\pi, (\hat{\mathsf{cm}}, \mathsf{cm}'), t, pp')$；知识可靠性将 witness 中 $(F,\hat{W},\hat{b})$ 与 $\hat{\mathsf{cm}}$ 绑定（附录 C）。

**本仓现实现（过渡，须向 B′ 收敛）：** Pedersen 链外承诺 —

**公式（与 `commitment.rs` 一致）：**

$$
C_W = r \cdot G + \sum_{i=0}^{N_W-1} H(i) \cdot w_i \cdot G,
\quad H(i) = \mathrm{SHA256}(\texttt{"cp-snark-model-gen"} \,\|\, \mathrm{le64}(i)) \bmod q_1
$$

| 项 | 定案 |
|----|------|
| 承诺对象 | **完整** $\mathbf{W}^*$（1219 维），非 178 维轨迹 |
| 公开产物 | `ModelCommitmentBundle`：`point_hex`、`digest_hex`、`num_weights=1219` |
| 客户端验证（P1a） | `verify_pedersen_open_model(point_hex, weights, blind_hex)` |
| Opening 传递 | MVP：`ProtocolArtifacts.model_opening`（`weights` + `blind_hex`）；生产可换 Spartan `CPS.Comm` / NIZK $\pi_{\mathrm{open}}$ |
| 链外代价 | $O(N_W)$ 群标量乘，1219 维 **毫秒级**；对 prove **≈0%** |

**状态：** Plan A.2 ✅（Pedersen MVP）；**论文闭合** → **M-B′** 改 `CPS.Comm` + 统一 `CPS.Ver`。

#### 1.4.3 $R_W$：Merkle（**A′ 大模型 / 过渡**；**network A 非论文主路径**）

**何时需要 Merkle：** $|W|\gtrsim 10^6$ 无法全量 `CPS.Comm` / Pedersen 循环；或 B′ 未接线前的工程过渡。  
**network A：** 论文**不用** Merkle；$N_W=1219$ 全量 Comm **毫秒级**，绑定靠 **CP-SNARK** 强于 Merkle 抽检。

| 环节 | 定案 | 实现 |
|------|------|------|
| **叶节点** | $L_i = \mathrm{SHA256}(\mathrm{bytes}(\mathrm{embed}(W^*_i)))$ | `bind_l1::merkle_root_w_star` |
| **树** | 二叉 SHA256 Merkle（奇数叶复制配对） | 同上（链外建树） |
| **根 $R_W$** | 32 B hex，写入 `w_star_merkle_root_hex` | `prove/pipeline.rs` |
| **访问集** | `UsedIndices = { i_j \mid j \in 0..J-1 }` | `j_to_wstar_index.json`（$j \to i$） |
| **链外快检** | `check_l1_ptmul_bindings`：$a_j = W^*_{i_j}$ | Plan A.3 ⚠️ **已有** |
| **电路内（待做）** | 对每个 $j$：`MerkleVerify`（Poseidon） | **M1-L1**（A′ 专用） |
| **大模型** | $|W| \gtrsim 10^6$：Setup **仅** Merkle 流式建树；禁止全量 Pedersen 循环 | 见大模型专文 §2–§3 |

**network A 目标（B′）与过渡（A′）：**

```text
【B′ network A 目标】
Setup:  cm̂ ← CPS.Comm(W*)
Prove:  cm' ← CPS.Comm(aux);  π ← CPS.Prov(ϕ, (F,Ŵ,b̂, aux))
Verify: CPS.Ver(π, (cm̂, cm'), t) + 客户端 γ + M1 标量复算

【A′ 本仓过渡，非 A 论文必需】
Setup:  Pedersen C_W + Merkle R_W（bind_l1.rs）
Prove:  L1 + Poseidon MerkleVerify（M1-L1）+ π_ec + M5/M1
```

**禁止：** R1CS 内全量 Pedersen；SHA256 全路径进 R1CS；仅比 `digest_hex`。

#### 1.4.5 运算过程绑定模型（B′：$\phi$+M5；A′：L1/Merkle+M5）

**B′（network A）：** `CPS.Prov` 的 witness 含 $(F,\hat{W},\hat{b})$，$\phi$ 编码式 (9)(7)(10) + $\gamma$（**M5**）；`CPS.Ver` 联证 $\hat{\mathsf{cm}}$ — **非** Merkle 叶打开。

**A′（大模型/过渡）：** 证明中每次 PtMul 乘数须来自承诺 $\mathbf{W}^*$ 对应叶，且与 MAC 一致：

| 层 | 约束（对每个 $j = 0..J-1$） | R1CS 增量（A） | 状态 |
|----|---------------------------|----------------|------|
| **L1** | $w_{i_j} \cdot 1 = \texttt{vars\_para}[\mathrm{slot}(j)]$ | $\approx 178$ 条（$\Delta C \approx 484$ 含输入槽） | ❌ **未注入** `point_mult` |
| **L1′** | $\mathrm{MerkleVerify}$（**Poseidon**） | A′：$\approx 5.9\times 10^5$；**B′ 不要求** | ❌ 仅链外根比对 |
| **L2** | $a_j = \mathrm{OutMAC}_j(\mathbf{W}^*, x, \gamma)$（式 8–10） | **≈1.16×**（式 (10) 压缩） | → **M5** 按层 π |
| **连接** | L1/L1′ 钉住 EC 乘数；L2/M5 钉住 MAC 与运算 | — | M1 标量验 ≠ 电路绑定 |

**槽位（冻结）：** $\mathrm{slot}(j) = n_{\mathrm{bit}} + 3466 \cdot j$，$n_{\mathrm{bit}} = 128$（`bind_l1.rs`、`point_mult.rs`）。

**编码统一：** 承诺 / RLC / L1 均用 `curve::embed_u128_to_scalar`（16 B LE + `from_bytes_wide`）。

#### 1.4.6 Poseidon、防伪造与 P4′ 随机 Merkle 挑战（定案）

> **展开：** [`完整密码学交互与模型绑定-数学过程与复杂度.md`](./完整密码学交互与模型绑定-数学过程与复杂度.md) **§7.0、§7.7**

| 项 | 定案 |
|----|------|
| **Poseidon** | 电路内 Merkle 用 $\mathbb{F}_{q_1}$ 上 Poseidon（$\sim 200$–$400$ 约束/次）；链外可 SHA256；**禁止** SHA256 全路径进 R1CS |
| **算力不对称** | ❌ 不能保证「换整盘模型比 Setup 更贵」（均为 $O(N_W)$）；✅ 保证伪造不可行（$\mathrm{negl}(\lambda)$） |
| **T1 硬绑定** | UsedIndices 上 L1 + MerkleVerify（**必做**）；防推理时换权重 |
| **P4′ 随机挑战** | 客户端另采 $\mathcal{S}_{\mathrm{ch}}$，$\|S\|=k_c$（大模型建议 32–128）；P6 验 Merkle；**统计审计**，不替代 T1 |
| **检出概率** | $p_{\mathrm{hit}} \approx 1 - \binom{N_W-t}{k_c}/\binom{N_W}{k_c} \approx k_c t / N_W$（$t$ 个坏叶） |
| **约束增量** | $\Delta C \approx (k_w+k_c) \cdot D \cdot C_P$；仅 **A′** 电路内 Merkle 时计入 |

### 1.5 B′ 能保证什么 / 不能保证什么（network A，定理级）

> 依据：vPIN 附录 Fig.6–8、附录 C Soundness；[`完整密码学交互…`](./完整密码学交互与模型绑定-数学过程与复杂度.md) §5。

#### 1.5.1 在 B′ **完整实现**前提下（CP-SNARK 假设）

| 命题 | 能否保证 | 机制 |
|------|----------|------|
| 证明用的模型 = catalog 中 $\hat{\mathsf{cm}}$ 承诺的 $\mathbf{W}^*$ | ✅ | `CPS.Comm` 绑定 + `CPS.Ver` 知识可靠性 |
| 证明用的 $(F,\hat{W},\hat{b})$ 参与本次 $\phi$ 陈述 | ✅ | witness 含模型 + $\phi=\phi_{cnv}\land\phi_{pl}\land\phi_{fc}$ |
| 线性层同态运算（卷积/池化/FC）与式 (9)(7)(10)、$\gamma$ 一致 | ✅ | **须 M5** 将 $\phi$ 接进 `CPS.Prov`（非仅 EC-SNARK） |
| 密文 $C$ 与推理 $t$ 与证明一致 | ✅ | 附录 C（$C=\hat{C}$） |
| 比随机 Merkle 抽检更强的**硬绑定** | ✅ | 全关系 $R$ 一次陈述，非 $p_{\mathrm{hit}}$ 统计 |

#### 1.5.2 即使 B′ 也**不**保证（论文边界）

| 命题 | 原因 |
|------|------|
| 全 CNN 含 TReLU 的端到端 | TReLU 在**客户端**（Fig.5）；服务器只证 conv/pool/FC |
| 明文输入 $X$ 未篡改 | 须 $\mathsf{cm}_x$ 与 `Enc(X)` 闭合（本仓仍弱） |
| 跨会话偷换 $\hat{\mathsf{cm}}$ | 客户端须持久化 catalog 并拒绝对不上号的 cm |

#### 1.5.3 本仓**今天**能否保证？

| 条件 | 状态 | 后果 |
|------|------|------|
| 统一 `CPS.Ver(π,(cm̂,cm'),t)` | ❌ | cm̂ 与 π **未联证** |
| $\phi$ 含式 (9)(7)(10) + $(F,\hat{W},\hat{b})$ | ❌ `mac_proof=None` | **运算语义未进 $R$** |
| Pedersen 代替 `CPS.Comm` | ⚠️ 过渡 | 非论文承诺语义 |
| M1 客户端 $\gamma$ 标量验 | 待做 | 双检层，不替代 B′ |

**结论：** 论文 B′ **设计上能**绑「模型参数 + 服务器证明范围内运算」；**本仓未实现 B′+M5 前不能宣称**；M1-L1/Merkle 为 A′ 或过渡，**不能替代** B′ 对 network A 的论文闭合。

#### 1.5.4 B′ 闭合充要条件（编码检查表）

1. $\hat{\mathsf{cm}}\leftarrow\texttt{CPS.Comm}(\mathbf{W}^*)$（`commit_test.rs` / Spartan PC）。  
2. $\mathsf{cm}'\leftarrow\texttt{CPS.Comm}(aux)$，与 `comm_vars_para` 一致。  
3. **统一** `CPS.Ver`，客户端**只**持 catalog 的 $\hat{\mathsf{cm}}$。  
4. `CPS.Prov` 的 $\phi$ **显式含** $F,\hat{W},\hat{b}$ 与式 (9)(7)(10)（**M5**）。  
5. P4：$\gamma,\gamma'$ 仅客户端、进 transcript（**M1/M2**）。  
6. （产品）$\mathsf{cm}_x$ 绑真实 $x$。

缺 **3 或 4** → 可能有「承诺了一盘 $W$」+「另一条 EC 轨迹」，但**不能保证**本次运算用承诺核/FC 权重。

## 3. 总原则

1. **先让「承诺 + 证明」可信**（阶段 0→1），再挂 task3 与产品化。  
2. **先跨进程协议合规**（R0–R4），再 Rust 全量同态推理（R5）。  
3. **曲线嵌入不再排期**；承诺对齐 L1 / 完整 $\|W\|$（见阶段 1）。  
4. **network A 绑定主路径：** **B′**（`CPS.Comm/Ver` + **M5** $\phi$），非 Merkle 抽检（§1.5）。  
5. **CP-SNARK 编码顺序：** **M1 → M2**（可并行 **M-B′**）→ **M5** → M3 → M4；**M1-L1** 仅 A′/过渡（§5）。  
6. **两套 P0–P5 勿混读：** `CP-SNARK自检` §十二 = 命题优先级；本路线图 §4–§6 = 工程阶段。

## 12. 计算量预估摘要（network A）

> **完整推导、符号与 Spartan 分解：** [`CP-SNARK自检与计算量预估.md`](./CP-SNARK自检与计算量预估.md) §五–§十一。  
> **基准（实测）：** $C_{\mathrm{current}} \approx 638\,032$ 约束；prove **~201 s**；证明 **~259 KB**（178× PtMul + 2144× PtAdd）。

### 12.1 增强层级对照

| 方案 | R1CS 约束 $C$ | 相对当前 | prove 时间（估） | 证明大小（估） | 语义 |
|------|---------------|----------|------------------|----------------|------|
| **当前** | 638 032 | **1.00×** | **~201 s** | **~259 KB** | 仅 EC gadget |
| **+ L1 等式绑定** | ≈638 500 | **1.001×** | ~202 s | ~260 KB | 乘数 = 公开/承诺 $w_i$ |
| **+ L1′ Merkle** | ≈642k–691k | **1.01–1.08×** | ~203–220 s | ~262–290 KB | 乘数 = $W^*$ 叶 + 路径 |
| **+ L2（式 (10) 压缩）** | ≈740k | **1.16×** | ~230–270 s | ~300–340 KB | MAC/FC RLC in-circuit |
| **+ L2 naive（无压缩）** | ≈4.8M | **7.6×** | ~25–35 min | ~0.6–1 MB | **禁止** |
| **+ L3 端到端** | $10^6$–$10^7$ | **2–15×+** | 分钟–小时 | MB 级 | 论文完整 vPIN |

### 12.2 关键增量公式

| 项 | 公式 | network A 数值 |
|----|------|----------------|
| L1 等式 | $\Delta C_{L1} \approx (k_w + \|x\|) \cdot C_{eq}$，$C_{eq} \approx 1\text{–}3$ | $k_w=178$，$\Delta C \approx \mathbf{484}$（**<0.1%**） |
| L1′ Merkle | $\Delta C_{L1'} \approx k_w \cdot c_h \cdot \log_2 N_W$ | $178 \times 10 \times c_h$，$c_h=2\text{–}30$ → **+0.6%–8%** |
| L2 FC 压缩 | $(g_1+g_2) \cdot C_{\mathrm{PtMul}}$ | $(16+10) \times 3464 \approx 90\,064$（**+14%**） |
| L2 FC naive | $g \cdot h \cdot C_{\mathrm{MAC}}$ | $\approx 4.19 \times 10^6$（**7.6×**） |

### 12.3 链外 Setup（不占 R1CS）

| 操作 | 复杂度 | network A |
|------|--------|-----------|
| Pedersen `cm_W` | $O(N_W)$ 标量乘 | 1219，毫秒级 |
| Pedersen `cm_x` | $O(\|x\|)$ | 64–784 量级 |
| Merkle 建树 $R_W$ | $O(N_W)$ 哈希 | 1219 叶，毫秒级 |
| 大模型 Merkle | 流式 $O(\|W\|)$，公开 $O(1)$ 根 | 见大模型专文 |

### 12.4 工程结论（排期用）

1. **M1-L1（w 进约束）** 约束代价可忽略（**≈1.001×**），工作量在电路接线与索引映射。  
2. **L1′ Merkle 进电路** 为完整 $N_W$ 承诺下的推荐路径（**1.01–1.08×**），优于 naive L2。  
3. **M5 按层 π** 必须带式 (10) 压缩；禁止 naive MAC（**7.6×**）。  
4. **benchmark**（阶段 6.3）：L1/L1′/M5 完成后用 `benches/cost_report.rs` 实测修正上表。

### 13.3 vPIN 论文原生路径 vs 本仓现状

**论文（Figure 6–8，附录）：**

```text
Setup:  cm̂ ← CPS.Comm(W, r, pp)           // 模型 W
Infer:  cm' ← CPS.Comm(aux, r2, pp)        // 辅助 witness（ϕ_cnv/pl/fc）
        π   ← CPS.Prov(ϕ, (F,Ŵ,b̂,aux), pp)
Verify: CPS.Ver(π, cm=(cm̂,cm'), t, pp)   // 承诺与证明一体验证
```

- 绑定靠 **CP-SNARK 知识可靠性**：证明中的 witness 必须与 **同一** `CPS.Comm` 承诺一致。
- **无** 单独 Merkle 树；**无** 链外自定义 Pedersen（`commitment.rs` 为复现扩展）。
- `aux` 含 PtMul/PtAdd 轨迹 witness；`cm'` 与 `cm̂` 一并进入 `CPS.Ver`。

**本仓偏离（诚实）：**

| 论文对象 | 本仓实现 | 差距 |
|----------|----------|------|
| `CPS.Comm(W)` | 自定义 Pedersen `commit_model(load_w_star)` | 算法不同；未接入 Spartan `CPS.Ver` |
| `CPS.Comm(aux)` | `comm_vars_para`（`circuit_prove` 内部分块 PC） | 仅证子电路，**未**与 `cm_W` 链接 |
| `CPS.Ver(π,cm,t)` | 子电路 `my_lib_verify` + 链外 opening | **无** 统一 CP 验证 |
| 权重进约束 | `bind_l1` 链外检查 | L1/L1′ **未**进 R1CS（§5 M1-L1） |

**原仓库线索：** `commit_test.rs` / `my_lib_prove` 已实现 Spartan 分块 witness 承诺 — 论文 `cm'` 方向的参考实现，但 **未** 与 `cm_W` 做 CP 链接。

### 13.4 四条可落地的绑定实现路线（综合文献 + 本仓）

#### 路线 A — **M1-L1 + L1′**（当前定案，Spartan R1CS 友好）

```text
链外: Pedersen(cm_W) + Merkle(R_W)
电路: ∀j: vars_para[slot(j)] = embed(W*[i_j])
      ∀j: MerkleVerify(R_W, leaf_{i_j}, path_j)
后续: M5 证 a_j = OutMAC_j(W*, x, γ)  // 运算语义
```

- **优点：** 与现有 `point_mult` R1CS 栈兼容；L1 代价 ≈1.001×（§12）。
- **缺点：** 三套承诺（Pedersen / Merkle / `comm_vars_para`）需 transcript 顺序固定；非论文原生 `CPS.Comm(W)`。
- **参考：** 大模型 Merkle 与 Artemis 批评的「电路内重算 Poseidon」之对比 — 我们仅对 **$k_w$ 次打开** 付 Merkle 代价。

#### 路线 B — **论文还原：Spartan CPS.Comm + CPS.Ver**（中期）

```text
Setup:  cm_W = Spartan/Hyrax PC.Commit(encode(W*))
Prove:  cm_aux = PC.Commit(vars_para 块); π = my_lib_prove(...)
Verify: 扩展 CPS.Ver：联证 cm_W、cm_aux 与 R1CS
```

- **优点：** 与 vPIN 定理叙述一致；`comm_vars_para` 已有代码。
- **缺点：** 需实现 **CP 链接**（外部 `cm_W` ↔ 证明内 witness）；1219 维全量 PC 是否可行要 benchmark。
- **参考：** vPIN 附录 Fig.6–8；`commit_test.rs`。

#### 路线 C — **Artemis 式 CP-link**（长期 / 若迁移 Halo2 或扩展 Spartan）

- 外部：KZG/IPA 多项式承诺 `c_i = PC.Commit(w_i)`。
- 证明内：随机 $\alpha,\beta$ 线性组合 + `PC.Eval` 链外打开，**避免** 电路内重算承诺。
- **Artemis 实测：** VGG 承诺开销 11.5× → 1.2×（相对 naive 重算）。
- **本仓：** Spartan 非 Plonkish；**不能** 直接搬 `cp_link`；若保留 Spartan，需研究 Hyrax PC 的 Eval 链接 analogue。

#### 路线 D — **EZKL 式全电路**（不对齐 vPIN AHE，仅作对照）

- 模型权重作为 **私有 witness** 编入 ONNX→Halo2 电路；registry 存 hash。
- **不适用** 本仓「AHE 推理 + 轻量 EC gadget」架构，但可参考 **on-chain modelHash** 产品层（task3 / ERC-7992）。

| 阶段 | 动作 | 绑定语义 | 文献依据 |

### 14.3 电路内 MerkleVerify（要点）

- 叶：$L_i = H_{\mathrm{leaf}}(\iota(W^*_i))$；路径验证：$h_{\ell+1}=H(h_\ell\|s_\ell)$ 或交换顺序由 $b_\ell$ 决定；$h_D=R_W$。
- **SHA256 进 R1CS** 约 $k_w D \times 2\times 10^4 \gg C_0$ → **禁止**；**Poseidon** 约 $5.9\times 10^5$ 约束（A 网）可接受。
- 与 L1 联立：$\mathrm{MerkleVerify}\land(\iota_j\cdot 1=a_j)\land R_{\mathrm{PtMul},j}$。
