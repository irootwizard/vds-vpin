# 模型权重格式规范

> **最后更新**：2026-06-23  
> **AHE 全流程**：[ahe-数据与模型预处理流程.md](./ahe-数据与模型预处理流程.md)  
> **关联**：输入数据见 [数据集格式与上传规范.md](./数据集格式与上传规范.md)；预处理见 [预处理与模型格式适配.md](./预处理与模型格式适配.md)

本文定义 vPIN **可注册、可推理** 的模型权重契约，并收录 PyTorch、Hugging Face、Kaggle、ONNX 等常见格式的**识别规则**与**转换路径**。

---

## 1. 推理路径与格式分层

vPIN 有两条消费权重的链路，格式要求不同：

| 链路 | 用途 | 接受格式 | 状态 |
|------|------|----------|------|
| **AHE 同态推理** | Network A/B WS 会话、`homomorphic_network_a.py` | **npy bundle**（4 文件） | ✅ A、B 已打通 |
| **CP-SNARK / 注册元数据** | `POST /api/v1/models`、Rust `model/` | **model_export.json** | ✅ 卷积核；FC trace 待补 |
| **明文训练** | `model_training/network_*` | `checkpoint.pt` | 训练栈内部 |

**原则**：外部平台权重（HF `safetensors`、Kaggle `.pth`、ONNX 等）**不能直传 AHE**；须先训练栈或导出脚本转为 **npy bundle** 或 **model_export.json**。

## 2. AHE npy bundle（主格式）

### 2.1 文件清单（按网络）

定义于 `vpin-client/vpin_client/models/weights_layout.py`：

| 网络 | weight_fc1 | bias_fc1 | weight_fc2 | bias_fc2 | Pool |
|------|------------|----------|------------|----------|------|
| **A** | `weight_fc1_64_16.npy` | `bias_fc1_16.npy` | `weight_fc2_16_10.npy` | `bias_fc2_10.npy` | 4×4, stride 4 |
| **B** | `weight_fc1_64_32.npy` | `bias_fc1_32.npy` | `weight_fc2_32_10.npy` | `bias_fc2_10.npy` | 4×4, stride 4 |
| **C** | `weight_fc1_256_16.npy` | `bias_fc1_16.npy` | `weight_fc2_16_10.npy` | `bias_fc2_10.npy` | 2×2, stride 2 |
| **D** | `weight_fc1_256_32.npy` | `bias_fc1_32.npy` | `weight_fc2_32_10.npy` | `bias_fc2_10.npy` | 2×2, stride 2 |
| **E** | `weight_fc1_256_64.npy` | `bias_fc1_64.npy` | `weight_fc2_64_10.npy` | `bias_fc2_10.npy` | 2×2, stride 2 |

**卷积核**：Network A/B 为 **固定 Sobel 型 3×3**（同态引擎内置），**不在 npy 包内**；仅 FC 权重入包。

### 2.2 数组形状与 dtype

| 文件 | 形状 (Network A) | 形状 (Network B) | 推荐 dtype |
|------|------------------|------------------|------------|
| weight_fc1 | `(64, 16)` | `(64, 32)` | `float64` |
| bias_fc1 | `(16,)` | `(32,)` | `float64` |
| weight_fc2 | `(16, 10)` | `(32, 10)` | `float64` |
| bias_fc2 | `(10,)` | `(10,)` | `float64` |

- 布局为 **列主习惯**：`fc.weight.T` 自 PyTorch 导出（见 `model_training/network_a/export_weights.py`）。
- 推理时引擎内部 `astype(float64)` 再 `real_to_fixed_point(..., bits=16)`。
- 校验：`format_adapter.validate_npy_bundle()` 检查文件存在与非空形状。

### 2.3 打包与交付形态

| 形态 | 说明 |
|------|------|
| **目录** | 4 个 `.npy` 同目录，`weights_dir` 指向该路径 |
| **ZIP** | zip 根或任意子路径含上述 4 文件名（按 basename 匹配） |
| **注册** | `POST /api/v1/models` 字段 `npy_bundle` → 解压至 `data/models/uploads/{id}/npy/` |

### 2.4 截断计划（与权重绑定）

同态解密依赖 **本征移位**，非任意截断：

| 参数 | Network A/B 默认 | 含义 |
|------|------------------|------|
| `shift_pool` | 26 | pool 输出定点尺度（`from_bits`） |
| `shift_fc1` | 32 | FC1 输出移位 |

训练导出时写入 `truncation_config.json` / checkpoint `plan` 字段；AHE 引擎按 registry 或内置默认加载。

### 2.5 官方导出命令

```powershell
.\.venv\Scripts\python.exe -m model_training.network_a.export_weights --run-dir model_training\outputs\<run_id>
.\.venv\Scripts\python.exe -m model_training.network_a.register_backend --weights-dir model_training\outputs\<run_id>
```

## 3. model_export.json（CP-SNARK / 注册）

### 3.1 最小 schema

```json
{
  "network_id": "A",
  "conv_filter_flat": ["1", "0", "1", "2", "0", "2", "1", "0", "1"],
  "pool": {
    "kernel": 2,
    "stride": 2,
    "inv_k_squared_fp": "256"
  },
  "fc": []
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `network_id` | `"A"`…`"E"` | 拓扑标识 |
| `conv_filter_flat` | 字符串整数数组 | 3×3 卷积核展平（9 元），大整数用字符串 |
| `pool` | object | 池化核、步长、定点倒数 |
| `fc` | array | FC 层权重列表（CP-SNARK 路径；可为空，待 trace 导出补全） |

示例文件：`src/cp-snark-full/model_store/models/vpin-network-a/model_export.json`

### 3.2 检测规则

`format_adapter.detect_format()`：`.json` 且含 `conv_filter_flat` 或 `fc` → `MODEL_EXPORT_JSON`。

### 3.3 注册 API

`POST /api/v1/models`（multipart）：

- `weights`：单个 `model_export.json` 文件
- 或 JSON body `ModelRegisterRequest` + `weights_path`

## 4. 外部平台格式收录

### 4.1 总览对照表

| 平台 / 来源 | 常见格式 | vPIN 识别 | AHE | CP-SNARK | 转换方式 |
|-------------|----------|-----------|-----|----------|----------|
| **本仓库训练导出** | 目录 4×`.npy` | `AHE_NPY_BUNDLE` | ✅ | — | 直接使用 |
| **本仓库训练 checkpoint** | `checkpoint.pt` | `CHECKPOINT_PT` | ⚠️ | — | `export_weights.py` |
| **ZIP 含 4×npy** | `.zip` | `AHE_NPY_BUNDLE` | ✅ | — | `POST models` npy_bundle |
| **model_export.json** | `.json` | `MODEL_EXPORT_JSON` | ❌ | ✅ | `POST models` weights |
| **单文件 `.npy`** | 任一层权重 | `UNKNOWN` | ❌ | ❌ | 需完整 bundle |
| **PyTorch Hub / 自训** | `.pth` / `.pt` | `CHECKPOINT_PT` | ⚠️ | — | 须匹配 Network A/B 结构后导出 |
| **Hugging Face Hub** | `model.safetensors` / `pytorch_model.bin` | 未自动识别 | ❌ | ⚠️ | 自定义导出脚本 → npy |
| **Hugging Face** | `onnx/model.onnx` | 未自动识别 | ❌ | ❌ | ONNX 解析 → 重训或手写导出 |
| **Kaggle Kernel 输出** | `.pth` / `.h5` | 同 PyTorch/Keras | ❌ | ❌ | 见 §4.3 |
| **TensorFlow / Keras** | `.h5` / SavedModel | 未自动识别 | ❌ | ❌ | 权重映射到 FC 后导出 npy |
| **ONNX** | `.onnx` | 未自动识别 | ❌ | ❌ | 仅含 FC 时可脚本提取 |
| **LeNet / 经典 MNIST CNN** | 5×5 conv + pool | 拓扑不匹配 | ❌ | ❌ | 须改为 vPIN A–E 拓扑重训 |

### 4.2 Hugging Face Hub

典型仓库布局（图像分类）：

```
config.json
pytorch_model.bin   # 或 model.safetensors
preprocessor_config.json
```

| 格式 | 说明 | vPIN 处理 |
|------|------|-----------|
| **safetensors** | 推荐存储，键名为 `fc1.weight` 等 | `safetensors.torch.load_file` → 映射到 vPIN `fc1/fc2` → `export_weights` 同类逻辑 |
| **pytorch_model.bin** | Pickle 权重 | `torch.load` → 同上 |
| **ONNX** | 部分 Hub 模型提供 | 不直接支持；需 `onnx numpy` 提取 MatMul/Gemm |
| **Transformers 分类头** | 非 vPIN 拓扑 | **不可直转**；仅可借用 FC 权重若维度巧合（极少） |

**推荐流程**：

1. 在 `model_training/network_a` 用官方 MNIST **重训**（保证拓扑与截断一致）；
2. 或从 HF 下载后写 **一次性映射脚本**（仅当层名与形状与 Network A 一致）。

```python
# 示例骨架：HF state_dict → vPIN npy（须自行核对键名与形状）
import torch, numpy as np
from safetensors.torch import load_file

sd = load_file("model.safetensors")  # 或 torch.load("pytorch_model.bin")
w1 = sd["fc1.weight"].numpy().T.astype(np.float64)
np.save("weight_fc1_64_16.npy", w1)
# ... bias_fc1, weight_fc2, bias_fc2
```

### 4.3 Kaggle

| 类型 | 说明 |
|------|------|
| **竞赛提交** | `submission.csv`（label 列）— **不是模型权重** |
| **Kernel Output** | 用户保存的 `.pth` / `.h5` — 按 §4.2 / §4.4 转换 |
| **Dataset 中的预训练权重** | 多为 LeNet/VGG 变体 — 拓扑不符时需重训 |

Kaggle 无统一权重 schema；以 **文件扩展名 + `detect_format()`** 为准。

### 4.4 PyTorch checkpoint（训练栈内部）

`model_training/network_a/export_weights.py` 读取：

```python
payload = torch.load("checkpoint.pt", map_location="cpu", weights_only=False)
state_dict = payload["state_dict"]  # NetworkA 模块
```

期望模块：`fc1`, `fc2`（`nn.Linear`），卷积为固定 buffer 非 checkpoint 重点。

### 4.5 ONNX / TensorFlow / Keras

| 格式 | vPIN 态度 |
|------|-----------|
| `.onnx` | 检测为 `UNKNOWN`；可用 `onnx` 工具链提取常量，但 conv/pool 须与 A–E 一致 |
| `.h5` / SavedModel | 未集成；需手工导出 FC 权重为 npy |
| TFLite | 不支持 |

## 5. 格式自动检测

工具：`vpin-client/vpin_client/models/format_adapter.py`

```python
from pathlib import Path
from vpin_client.models.format_adapter import detect_format, validate_npy_bundle

probe = detect_format(Path("weights.zip"))
# FormatProbe(format=AHE_NPY_BUNDLE, network='A', detail='zip npy bundle', ...)

ok, errs = validate_npy_bundle(Path("weights_dir"), "A")
```

| `ModelFormat` 枚举 | 含义 |
|--------------------|------|
| `AHE_NPY_BUNDLE` | 可 AHE 推理 |
| `MODEL_EXPORT_JSON` | 可 CP-SNARK 注册 |
| `CHECKPOINT_PT` | 需 `export_weights` |
| `UNKNOWN` | 需人工转换 |

## 6. 服务端注册与存储

### 6.1 Registry 字段（`data/models/registry.json`）

| 字段 | 说明 |
|------|------|
| `id` | 模型 ID，如 `cnn-mnist-trained` |
| `network` | `A`–`E` |
| `topology` | 如 `cnn_mnist_v1` |
| `weights_dir` | npy bundle 目录（AHE 优先） |
| `storage_path` | model_export.json 或 bundle 根 |
| `commitment_digest` | 权重 SHA256（可选） |

### 6.2 HTTP 上传

| 端点 | 字段 | 格式 |
|------|------|------|
| `POST /api/v1/models` | `npy_bundle` | `.zip` 含 4×npy |
| `POST /api/v1/models` | `weights` | `model_export.json` |

前端：`ModelWarehouseView.vue` + `vpinApi.js` → `uploadModel()`。

## 7. 拓扑约束（为何不能通吃 HF/Kaggle 模型）

vPIN Network A–E 论文拓扑约束：

- 输入：32×32 pad 后单通道，**固定 3×3 conv**，TReLU，pool（A/B：4×4 s4；C–E：2×2 s2）
- 可训练部分主要为 **两层 FC**；AHE 包只含 FC
- 常见 HF `mnist` 分类模型（LeNet、SimpleCNN）卷积可训练、pool 不同 → **同态引擎不兼容**

因此：**收录外部格式的意义是明确转换与拒绝条件**，而非宣称任意 Hub 模型可一键推理。
