# OVDS 实际应用多模态数据方案

## 一、方案概述

### 1.1 背景
OVDS (Optimized Verifiable Data Streaming) 基于 VADS 协议，支持对多模态数据（文本、图片、音频、视频等）进行可验证的流式存储和查询。

### 1.2 核心特性
- **多模态支持**：支持文本、图片、音频、视频等多种数据类型
- **无损编码**：图片支持 PNG、WebP、TIFF 等无损格式
- **分块处理**：大文件自动分块，支持随机查询
- **可验证性**：基于 BLS 签名和 RSA Accumulator 提供完整性验证
- **客户端轻量**：客户端只需保存密钥和索引信息

### 1.3 技术架构
- **密码学基础**：BLS 签名 + RSA Accumulator
- **椭圆曲线**：BN254 (Type 3 非对称配对)
- **RSA 模数**：3072 位（128 位安全性）
- **安全参数**：λ = 128 bits
- **协议实现**：`src/vads_lib.py`（VADS 密码层，OVDS 主流程唯一依赖）

### 1.4 代码库范围说明

本方案对应的 OVDS 主流程仅基于 **VADS**（`src/vads_lib.py`）。

仓库中 `src/additional/avds_lib.py` 与 `src/additional/clvc_aux.py` 实现的是**另一套 AVDS**（q=2 树 + CLVC 向量承诺），用于独立实验或对比，**不是**本多模态方案及 OVDS 主流程的一部分。集成、部署或阅读协议流程时请勿与 AVDS 模块混用；完整协议说明见 `OVDS协议完整流程.md`；工程与服务设计见 `document/OVDS工程优化方案.md`、`document/OVDS数据托管服务器技术文档.md`。

## 二、数据预处理流程

### 2.1 文本数据处理流程

```
文本数据 → UTF-8编码 → 字节流 → 整数转换 → VADS数据项
```

**处理方式**：
1. **小文本**（< 1MB）：直接转换为整数
2. **大文本**（≥ 1MB）：分块处理，每块独立作为数据项
3. **可选哈希**：使用 SHA-256 哈希固定长度（但会丢失原始数据）

### 2.2 图片数据处理流程

```
图片文件 → 无损编码（PNG/WebP/TIFF）→ 字节流 → 整数转换 → VADS数据项
```

**无损编码格式选择**：
- **PNG**：通用性好，兼容性强，适合简单图像
- **WebP（无损）**：压缩率更高，现代浏览器支持
- **TIFF**：专业用途，支持更多元数据

**处理策略**：
1. **小图片**（< 1MB）：直接无损编码为整数
2. **大图片**（≥ 1MB）：先无损编码，再分块处理

### 2.3 其他多媒体数据处理流程

```
音频/视频文件 → 格式转换（可选）→ 字节流 → 分块处理 → VADS数据项
```

**处理原则**：
- 所有数据最终转换为整数
- 大文件必须分块处理
- 保持数据完整性（使用哈希验证）

## 三、数据存储流程

### 3.1 单文件存储流程

```
1. 文件预处理
   ├─ 计算文件哈希（SHA-256）
   ├─ 确定分块大小（默认 1MB）
   └─ 生成文件元数据

2. 数据分块
   ├─ 将文件分割为多个块
   ├─ 每个块转换为整数
   └─ 记录块索引和偏移量

3. 添加到 VADS
   ├─ 对每个块执行 append_client（生成签名）
   ├─ 发送到服务器执行 append_server（验证并存储）
   └─ 记录 VADS 索引

4. 保存客户端索引
   ├─ 文件ID → 块映射关系
   ├─ VADS索引 → 块信息映射
   └─ 文件元数据（哈希、大小、块数等）
```

### 3.2 批量文件存储流程

```
1. 文件列表预处理
   ├─ 遍历所有文件
   ├─ 计算每个文件的哈希和大小
   └─ 生成文件清单

2. 并行处理（可选）
   ├─ 多线程/多进程处理
   ├─ 每个文件独立分块和编码
   └─ 批量提交到 VADS

3. 索引管理
   ├─ 维护全局文件索引
   ├─ 记录每个文件的块索引列表
   └─ 定期备份索引信息
```

## 四、数据查询流程

### 4.1 单文件查询流程

```
1. 客户端查询
   ├─ 根据文件ID查找块索引列表
   ├─ 生成查询请求（可以随机顺序）
   └─ 发送查询请求到服务器

2. 服务器处理
   ├─ 根据索引从 DB 检索数据
   ├─ 生成非成员证明（RSA Accumulator）
   └─ 返回数据项和证明

3. 客户端验证
   ├─ 验证 BLS 签名
   ├─ 验证 RSA Accumulator 非成员证明
   └─ 如果验证通过，接受数据

4. 数据重组
   ├─ 按块索引排序
   ├─ 合并所有块
   └─ 验证文件哈希
```

### 4.2 批量查询流程

```
1. 多文件查询
   ├─ 获取多个文件的块索引列表
   ├─ 合并所有查询索引
   └─ 使用 query_star 批量查询

2. 批量验证
   ├─ 使用 verify_star 批量验证
   ├─ 验证聚合签名
   └─ 验证聚合非成员证明

3. 数据分发
   ├─ 根据文件ID分组
   ├─ 每个文件独立重组
   └─ 返回所有文件数据
```

### 4.3 随机查询特性

**关键点**：
- ✅ **支持随机顺序查询**：每个块是独立的数据项，可以任意顺序查询
- ✅ **支持并发查询**：可以同时查询多个块，提高效率
- ⚠️ **恢复时需要排序**：查询后必须按 `chunk_index` 排序才能正确重组

## 五、客户端存储方案

### 5.1 必须保存的信息

#### 5.1.1 秘密密钥 (secret_key.pkl)
```
sk = {
    'alpha': α,      # 秘密值，用于生成签名（必须加密存储）
    'cnt': cnt,      # 当前计数器值
    'vk': vk         # 验证密钥（包含公钥信息）
}
```
**安全要求**：必须加密存储，建议使用 AES-256 加密

#### 5.1.2 验证密钥 (verification_key.pkl)
```
vk = {
    'group': group,      # 双线性配对群
    'g': g,              # 生成元
    'A': A,              # 公钥
    'u': u,              # G1 群元素
    'n': n,              # RSA 模数
    'h': h,              # RSA Accumulator 初始值
    'Acc_0': Acc_0,      # 初始累加器值
    'HG': HG,            # 哈希函数
    'HPrime': HPrime     # 素数哈希函数
}
```
**说明**：可以公开，但建议保存以便离线验证

#### 5.1.3 文件索引 (file_index.json)
```json
{
  "file_id_1": {
    "metadata": {
      "file_hash": "sha256哈希",
      "file_size": 文件大小,
      "total_chunks": 总块数,
      "chunk_size": 每块大小,
      "file_path": "原始文件路径",
      "created_at": "创建时间"
    },
    "chunk_indices": [
      {"vads_index": 0, "chunk_index": 0},
      {"vads_index": 1, "chunk_index": 1},
      ...
    ]
  }
}
```

#### 5.1.4 数据映射 (data_mapping.json) - 可选
```json
{
  "0": {
    "type": "chunk",
    "file_id": "file_id_1",
    "chunk_index": 0
  },
  "1": {
    "type": "single",
    "data_hash": "哈希值"
  }
}
```

### 5.2 不需要保存的信息

- ❌ **原始数据**：可以从服务器查询恢复
- ❌ **签名和标签**：服务器存储，查询时返回
- ❌ **服务器状态**：服务器维护（DB、R、Acc_R 等）

### 5.3 存储结构

```
client_storage/
├── secret_key.pkl          # 秘密密钥（加密）
├── verification_key.pkl     # 验证密钥
├── file_index.json          # 文件索引
├── data_mapping.json       # 数据映射（可选）
└── backup/                  # 备份目录
    ├── file_index_backup.json
    └── ...
```

## 六、数据恢复流程

### 6.1 单文件恢复流程

```
1. 查找文件索引
   ├─ 根据文件ID或文件路径查找
   └─ 获取所有块的 VADS 索引

2. 查询所有块
   ├─ 可以随机顺序查询
   ├─ 使用 query 或 query_star
   └─ 验证每个块的证明

3. 数据重组
   ├─ 按 chunk_index 排序
   ├─ 将整数转换回字节
   ├─ 合并所有块
   └─ 验证文件哈希

4. 保存恢复的文件
   ├─ 写入到指定路径
   └─ 记录恢复日志
```

### 6.2 批量恢复流程

```
1. 获取文件列表
   ├─ 从 file_index.json 读取
   └─ 筛选需要恢复的文件

2. 批量查询
   ├─ 收集所有文件的块索引
   ├─ 使用 query_star 批量查询
   └─ 批量验证

3. 并行重组
   ├─ 多线程处理不同文件
   ├─ 每个文件独立重组
   └─ 验证完整性

4. 保存所有文件
   └─ 写入到恢复目录
```

## 七、数据审计流程

### 7.1 单文件审计流程

```
1. 选择审计范围
   ├─ 指定文件ID
   └─ 获取该文件的所有块索引

2. 执行审计
   ├─ 调用 audit 函数
   ├─ 服务器生成审计证明
   └─ 返回 π_a（包含聚合签名和证明）

3. 验证审计结果
   ├─ 调用 judge 函数
   ├─ 验证聚合签名
   ├─ 验证 RSA Accumulator 证明
   └─ 返回验证结果（1=通过，0=失败）
```

### 7.2 全库审计流程

```
1. 获取所有索引
   ├─ 从服务器获取所有数据项索引
   └─ 或从客户端索引文件获取

2. 批量审计
   ├─ 可以分批审计（避免处理过大整数）
   ├─ 每批生成审计证明
   └─ 记录审计结果

3. 验证所有批次
   ├─ 逐个验证每批审计证明
   └─ 生成审计报告
```

## 八、数据更新流程

### 8.1 单块更新流程

```
1. 定位数据项
   ├─ 根据 VADS 索引查找
   └─ 验证旧数据签名

2. 生成新数据
   ├─ 创建新的 tag_i'
   ├─ 计算新签名 σ_i'
   └─ 更新 Acc_R（将旧 tag 加入 R）

3. 服务器更新
   ├─ 验证新签名
   ├─ 更新 DB[i]
   └─ 更新 R 集合和 z_star
```

### 8.2 文件级更新流程

```
1. 文件变更检测
   ├─ 计算新文件哈希
   ├─ 与旧哈希对比
   └─ 确定变更的块

2. 更新变更块
   ├─ 对每个变更块执行 update
   └─ 记录更新日志

3. 更新索引
   ├─ 更新文件元数据
   └─ 更新块索引映射
```

## 九、性能优化策略

### 9.1 分块大小优化

**建议值**：
- 小文件（< 10MB）：不分块，直接存储
- 中等文件（10MB - 100MB）：1MB 每块
- 大文件（> 100MB）：2-4MB 每块

**考虑因素**：
- 网络传输效率
- 查询响应时间
- 内存占用

### 9.2 批量操作优化

**Append 优化**：
- 使用 `append_client` 快速生成签名
- 批量提交到服务器
- 采样验证（大数据集时）

**Query 优化**：
- 使用 `query_star` 批量查询
- 并发查询多个块
- 缓存常用数据

### 9.3 索引优化

**文件索引**：
- 使用 JSON 格式便于查询
- 定期备份索引
- 支持增量更新

**数据映射**：
- 可选，用于快速查找
- 可以按需构建

## 十、安全考虑

### 10.1 密钥安全

- **秘密密钥加密**：使用 AES-256 加密存储
- **密钥备份**：安全备份到多个位置
- **密钥轮换**：定期更新密钥（需要迁移数据）

### 10.2 数据完整性

- **哈希验证**：每个文件计算 SHA-256 哈希
- **签名验证**：每次查询验证 BLS 签名
- **证明验证**：验证 RSA Accumulator 非成员证明

### 10.3 访问控制

- **客户端认证**：确保只有授权客户端可以 append
- **查询权限**：可以设置查询权限控制
- **审计日志**：记录所有操作日志

## 十一、错误处理

### 11.1 查询失败处理

```
查询失败 → 重试机制 → 记录错误 → 通知用户
```

### 11.2 验证失败处理

```
验证失败 → 记录失败信息 → 重新查询 → 报告异常
```

### 11.3 数据损坏恢复

```
检测到损坏 → 从备份恢复 → 重新验证 → 更新索引
```

## 十二、典型应用场景

### 12.1 图片存储系统

**流程**：
1. 用户上传图片 → 无损编码（PNG/WebP）
2. 分块存储到 VADS
3. 查询时随机获取块 → 重组图片
4. 定期审计验证完整性

### 12.2 文档管理系统

**流程**：
1. 文档转换为字节流
2. 分块存储
3. 支持版本控制（通过 update）
4. 批量查询和恢复

### 12.3 多媒体内容分发

**流程**：
1. 视频/音频文件分块
2. 分布式存储到多个 VADS 节点
3. CDN 加速查询
4. 客户端验证完整性
